# OpenCode: моя конфигурация

Перенос рабочей настройки OpenCode на другую машину: сабагенты, слэш-команды,
глобальные правила и провайдер RouterAI. Один скрипт — и всё как на работе.

Проверено на **OpenCode v2.0.29**, Windows 10/11 и macOS (bash 3.2+, включая M1/M2).

---

## Дома: просто скажи агенту

На домашней машине открой OpenCode и напиши:

```
настрой OpenCode из гитхаба: https://github.com/permyakov344-png/opencode-setup
```

Агент склонирует репозиторий, запустит `install.sh` (Mac) или `install.ps1`
(Windows), затем `verify`. Подробная пошаговая инструкция для агента лежит в
[`НАСТРОИТЬ.md`](НАСТРОИТЬ.md).

Если хочешь руками, без агента — те же команды в разделе «Быстрый старт».

### Про ключ RouterAI

Ключ в репозитории **не хранится**. Возможны три случая:

| Что на машине | Что сделает установщик |
|---|---|
| уже есть `~/.config/opencode/opencode.json` с рабочим ключом | **возьмёт этот ключ, ничего не спросит** |
| ключа нет, задан `$ROUTERAI_API_KEY` | возьмёт из переменной окружения |
| ни того, ни другого | один раз спросит и вставит в локальный конфиг |

То есть на домашней машине со своим ключом можно вообще ничего не передавать —
если конфиг уже настроен, ключ останется прежним, обновятся только модели,
агенты и команды.

Принудительно свой ключ:

```powershell
powershell -ExecutionPolicy Bypass -File install.ps1 -ApiKey "sk-..."
```

```bash
bash install.sh --api-key "sk-..."
```

## Быстрый старт

### macOS / Linux

```bash
# 1. Скачать конфигурацию
git clone https://github.com/permyakov344-png/opencode-setup.git ~/opencode-setup
cd ~/opencode-setup

# 2. Установить
bash install.sh
```

Проверка:

```bash
bash verify.sh
```

Ожидается: `ок: 15   предупреждений: 0   проблем: 0`.

Если OpenCode ещё не установлен:

```bash
brew install anomalyco/tap/opencode-v2     # или: npm install -g @opencode/cli
```

### Windows

```powershell
git clone https://github.com/permyakov344-png/opencode-setup.git $env:USERPROFILE\opencode-setup
cd $env:USERPROFILE\opencode-setup
powershell -ExecutionPolicy Bypass -File install.ps1
powershell -ExecutionPolicy Bypass -File verify.ps1
```

### После установки

Перезапусти OpenCode, набери `/` — в списке должны быть
`review`, `test`, `docs`, `sync`, `pro`, `flash`.
В списке сабагентов — `reviewer`, `tester`, `docs`.

## Модели

Провайдер — **RouterAI** (`https://routerai.ru/api/v1`), это не OpenRouter.

| Модель | Вход, ₽/M | Выход, ₽/M | Когда используется |
|---|---|---|---|
| `deepseek-v4.1-flash-1017` | 4,1 | 17,6 | по умолчанию, ~90% работы |
| `deepseek-v4-pro-0813` | 98,8 | 296 | `/pro`, сложные задачи |
| `deepseek-v4-flash-vision-exp` | 23 | 69 | картинки и скриншоты |

Модель по умолчанию задаётся в `config/opencode.json`:

```json
"model": "routerai/deepseek-v4.1-flash-1017"
```

**Важно:** модель хранится ещё и внутри сессии. Уже открытая сессия останется
на своей модели — переключить её можно командой `/flash`. Новые сессии берут
модель из конфига.

Сабагенты модели **не задают** — наследуют модель сессии. Так они работают
с любым провайдером и не падают с `model not found`, когда бесплатную модель
убирают из каталога.

## Что внутри

```
config/
├─ opencode.json     — провайдер RouterAI, модели, MCP
├─ AGENTS.md         — глобальные правила работы
├─ agents/           — сабагенты
│   ├─ reviewer.md
│   ├─ tester.md
│   └─ docs.md
└─ commands/         — слэш-команды
    ├─ review.md
    ├─ test.md
    ├─ docs.md
    ├─ sync.md
    ├─ pro.md
    └─ flash.md

install.ps1 / install.sh        — установка (Windows / macOS)
verify.ps1  / verify.sh         — проверка, только чтение
sync.sh                         — commit + pull --rebase + push самого репозитория
синхронизация.bat               — то же для Windows
НАСТРОИТЬ.md                    — пошаговая инструкция для агента на новой машине
```

Куда ставится: `~/.config/opencode` — глобальная конфигурация OpenCode.
Одна и та же на macOS, Linux и Windows (`%USERPROFILE%\.config\opencode`).

## Сабагенты

| Агент | Что делает | Чего не делает |
|---|---|---|
| `reviewer` | читает `git diff` и `git status`, ищет баги по серьёзности | не правит файлы, shell только для `git diff` / `git status` |
| `tester` | пишет и правит тесты, запускает их | не трогает прод-код, не ставит зависимости |
| `docs` | обновляет README, `docs/`, CHANGELOG | не меняет код; `AGENTS.md` правится вручную |

Модель — от сессии. Если нужна своя, добавь в шапку файла агента
`model: провайдер/модель`, но тогда он привязан к этой модели навсегда.

## Команды

| Команда | Что делает |
|---|---|
| `/pro <задача>` | переключить сессию на дорогую модель (сложная задача) |
| `/flash <задача>` | переключить сессию на дешёвую модель |
| `/review [цель]` | ревью текущих изменений через `reviewer` |
| `/test <файл>` | тесты для файла через `tester` |
| `/docs [цель]` | README и документация через `docs` |
| `/sync` | commit → `pull --rebase` → `push` текущего проекта |

## Порядок работы (из `AGENTS.md`)

1. Сделал фичу или фикс → `/test <файл>`, если есть тестовый фреймворк.
2. `/review` — только перед коммитом рискованных изменений. Мелкая правка — без ревью.
3. README обновляется сам и только если изменились запуск, установка, API, CLI, env
   или структура. Сабагент `docs` — только по прямой команде.
4. Одна строка, опечатка, форматирование → ничего не запускать.
5. Закончил задачу с изменениями в git-проекте → сам делает `add`, `commit`,
   `pull --rebase`, `push`. Слова «сохрани» ждать не нужно.
6. Модель по умолчанию дешёвая. Тяжёлая задача → подсказка про `/pro`.

## Безопасность

В репозитории **нет** и не должно быть:

- ключ RouterAI — в шаблоне стоит `__ROUTERAI_API_KEY__`, реальный ключ
  подставляется только на машине при установке;
- `service.json` — локальный пароль-токен сервера, установщик его не трогает
  и не копирует.

Хочешь держать ключ вне файла — замени `"apiKey"` в `opencode.json` на
`"{env:ROUTERAI_API_KEY}"` и задай переменную окружения. Установщик и `verify`
такую подстановку понимают.

## Синхронизация самого репозитория

Поменял правила или команды — запусти `sync.sh` (Mac) или `синхронизация.bat`
(Windows), либо `/sync` внутри OpenCode: `commit → pull --rebase → push`,
без `--force`.

Правки конфигурации ведутся **в репозитории**, а не в `~/.config/opencode`,
чтобы не разъехались. Схема: правишь `config/...` → `install` → `sync`.

## Если что-то не так

Сабагент пишет `<model not found>` — в шапке файла агента была удалённая модель.
Убери строку `model:` (агент возьмёт модель сессии) и повтори установку.

Если `verify` показывает `[нет]` — запусти установщик повторно, он не удаляет,
только копирует и делает бэкап.

Если OpenCode пишет `Free usage limit reached` — это квота бесплатных моделей
OpenCode, а не RouterAI. Платные модели `routerai/*` работают независимо.

## Требования

| | macOS | Windows |
|---|---|---|
| OpenCode | `brew install anomalyco/tap/opencode-v2` или `npm install -g @opencode/cli` | `npm install -g @opencode/cli` |
| Оболочка | bash 3.2+ (штатная) | PowerShell 5.1+ (штатный) |
| Git | `xcode-select --install` | [git-scm.com](https://git-scm.com) |

Ключ RouterAI нужен для любой модели `routerai/*`. Без него OpenCode работает,
но только на бесплатных моделях OpenCode.
